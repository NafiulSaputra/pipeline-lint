# DE007 `airflow-unsafe-catchup`

**Severity:** error · **Languages:** Airflow 2 and 3

`catchup=True` with a missing or dynamic `start_date` causes unplanned backfills.

## Why is this a problem?

With catchup enabled, the scheduler creates one run for every interval between `start_date` and
now that has not run yet. If `start_date` is missing or comes from `datetime.now()` or
`days_ago()`, it moves every time the DAG file is parsed, so the set of runs Airflow creates is
unpredictable. Combined with non-idempotent tasks, the resulting surprise backfill writes
duplicated or inconsistent data.

## What it detects

`catchup=True` on a DAG whose `start_date` (in the DAG arguments or in `default_args`, also
through a variable) is missing or computed with `now()`, `utcnow()`, `today()` or `days_ago()`.

## Example

```python
# Problematic
with DAG(
    dag_id="sync_orders",
    schedule="@daily",
    start_date=datetime.now() - timedelta(days=7),
    catchup=True,
):
    ...

# Predictable
with DAG(
    dag_id="sync_orders",
    schedule="@daily",
    start_date=pendulum.datetime(2026, 1, 1, tz="UTC"),
    catchup=True,
):
    ...
```

## Not flagged

- A fixed `start_date` such as `pendulum.datetime(2026, 1, 1, tz="UTC")`.
- A dynamic `start_date` with `catchup=False`: no backfill happens.
- A missing `start_date` when `default_args` comes from somewhere the linter cannot see.

## Note

Ruff's `AIR` rules flag dynamic DAG arguments in general. DE007 targets the specific
combination of catchup and a moving start date that causes unintended backfills.
