# DE006 `airflow-missing-retries`

**Severity:** warning · **Languages:** Airflow 2 and 3

An Airflow DAG without retries turns every transient failure into a failed run.

## Why is this a problem?

Network blips, warehouse locks, API rate limits and lost spot instances are normal in
production. Airflow's default is zero retries, so each of them fails the task, blocks
downstream tasks and waits for a human to clear it, often outside working hours. A few
retries with a delay absorb these failures automatically.

Retries are only safe when tasks are idempotent: see [DE001](DE001.md).

## What it detects

`DAG(...)`, `with DAG(...)`, `@dag(...)` or a bare `@dag` (from `airflow` or `airflow.sdk`)
whose `default_args` has no `retries`, or `retries` set to `0`.

## Example

```python
# Problematic
with DAG(
    dag_id="ingest_orders",
    default_args={"owner": "data-team"},
    schedule="@daily",
    start_date=pendulum.datetime(2026, 1, 1, tz="UTC"),
):
    ...

# Resilient
default_args = {
    "owner": "data-team",
    "retries": 3,
    "retry_delay": timedelta(minutes=5),
}
```

## Not flagged

- `default_args` that cannot be seen statically: imported from another module, returned by a
  function, merged with `{**base}`, or `DAG(**config)`.
- A variable as the retries value.
- Files that do not import Airflow.

## Known limitations

Retries set on individual tasks rather than in `default_args` are not detected.
