# DE002 `unscoped-overwrite`

**Severity:** warning · **Languages:** SQL, PySpark, Databricks notebooks

An overwrite without a partition scope replaces the entire table.

## Why is this a problem?

A daily job usually means to refresh one day of data. An overwrite without a scope deletes
every row in the table and keeps only what this run produced, so history disappears the first
time the job runs.

A common trap: adding `.partitionBy()` does **not** help. Under Spark's default
`spark.sql.sources.partitionOverwriteMode=static`, all partitions are still replaced. Only
`replaceWhere` (Delta), dynamic partition overwrite, or an explicit `PARTITION` clause limits
what gets deleted. When `.partitionBy()` is present, the DE002 message says so explicitly.

## What it detects

- PySpark: `.write.mode("overwrite")` and `.insertInto(table, overwrite=True)` without
  `replaceWhere` or dynamic partition overwrite in the writer chain.
- SQL: `INSERT OVERWRITE [TABLE] <table>` without a `PARTITION (...)` clause.

## Example

```python
# Problematic: replaces every day in the table
(daily.write.format("delta").mode("overwrite")
    .partitionBy("order_date")
    .saveAsTable("gold.daily_sales"))

# Scoped: replaces only the run date
(daily.write.format("delta").mode("overwrite")
    .option("replaceWhere", f"order_date = '{run_date}'")
    .saveAsTable("gold.daily_sales"))
```

```sql
-- Problematic
INSERT OVERWRITE TABLE gold.store_revenue
SELECT store_id, order_date, SUM(amount) FROM silver.orders
WHERE order_date = '{{ ds }}' GROUP BY store_id, order_date;

-- Scoped
INSERT OVERWRITE TABLE gold.store_revenue PARTITION (order_date = '{{ ds }}')
SELECT store_id, SUM(amount) FROM silver.orders
WHERE order_date = '{{ ds }}' GROUP BY store_id;
```

## Not flagged

- `.option("replaceWhere", ...)`, `.option("partitionOverwriteMode", "dynamic")` and the
  `.options(...)` equivalents.
- Files that enable dynamic mode for the whole session with
  `spark.conf.set("spark.sql.sources.partitionOverwriteMode", "dynamic")`,
  `SparkSession.builder.config(...)` or SQL `SET`.
- `writeTo(t).overwritePartitions()`, `writeTo(t).overwrite(condition)`, `createOrReplace()`.
- Streaming writes.

## Known limitations

A writer stored in a variable and finished on a later line
(`w = df.write.mode("overwrite")`, then `w.option("replaceWhere", ...).save()`) is flagged.
Full refreshes of small dimension tables are legitimate: suppress with
`# noqa: DE002`.
