# DE001 `non-idempotent-append`

**Severity:** error · **Languages:** SQL, PySpark, Databricks notebooks

Append-only writes duplicate data when the job is retried or re-run.

## Why is this a problem?

Pipelines are re-run all the time: the orchestrator retries a task after a timeout, an engineer
re-runs a failed day, a backfill replays a month. A plain `INSERT INTO` or an append-mode write
adds the same rows again on every run, silently producing duplicates and double-counted
metrics. An idempotent write gives the same result whether it runs once or five times.

## What it detects

- SQL: `INSERT INTO <table> ...` (with `SELECT` or `VALUES`).
- PySpark: `.write.mode("append")`, `.write.insertInto(table)` without `overwrite=True`,
  `.writeTo(table).append()`.

## Example

```sql
-- Problematic
INSERT INTO analytics.fct_orders
SELECT order_id, amount, order_date FROM raw.orders WHERE order_date = '{{ ds }}';

-- Idempotent: replace the processed window
DELETE FROM analytics.fct_orders WHERE order_date = '{{ ds }}';
INSERT INTO analytics.fct_orders
SELECT order_id, amount, order_date FROM raw.orders WHERE order_date = '{{ ds }}';

-- Idempotent: upsert on the business key
MERGE INTO analytics.fct_orders AS t
USING staged_orders AS s ON t.order_id = s.order_id
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *;
```

```python
# Problematic
orders.write.mode("append").saveAsTable("analytics.fct_orders")

# Idempotent: overwrite only this run's partition
(orders.write.format("delta").mode("overwrite")
    .option("replaceWhere", f"order_date = '{run_date}'")
    .saveAsTable("analytics.fct_orders"))
```

## Not flagged

- `INSERT OVERWRITE`, `MERGE`, `INSERT ... ON CONFLICT`, `INSERT OR REPLACE`, `INSERT IGNORE`,
  Databricks `INSERT INTO ... REPLACE WHERE`, `DeltaTable.merge(...)`.
- An append preceded in the same file by `DELETE FROM` or `TRUNCATE` of the same table, also
  when the delete is issued through `spark.sql("...")`. Table names are compared
  case-insensitively, and `orders` matches `sales.orders`.
- `insertInto(table, overwrite=True)`.
- Streaming writes (`writeStream`): exactly-once delivery comes from the checkpoint.

## Known limitations

A delete performed in another task or file is not visible. Suppress with `noqa` and a reason.
Append-only tables by design, such as audit logs, are a legitimate exception.

```sql
INSERT INTO audit.load_log VALUES ('orders', current_timestamp());  -- noqa: DE001
```
